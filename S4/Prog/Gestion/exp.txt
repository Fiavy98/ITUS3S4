=============================
CONTRAINTE FONDAMENTALE : GÉNÉRALISATION TOTALE
=============================

TOUT doit être généralisé. L'application ne "sait" pas qu'elle
gère du stock a priori. Elle gère des "entités métier" avec des
"attributs dynamiques", des "mouvements" et des "états".

Cela signifie :
- Les formulaires (JPanel) sont génériques → GenericFormPanel
- Les tableaux JTable sont génériques → GenericTableModel<T>
- Les classes métier héritent d'une base abstraite → BaseEntity
- On peut instancier un module "Bibliothèque", "Flotte de véhicules",
  ou "Stock alimentaire" sans modifier le code du framework
- Un "Article" n'est qu'une configuration d'une entité générique
- Les colonnes affichées en UI sont déclarées via metadata,
  pas codées en dur

II. SCHÉMA BASE DE DONNÉES POSTGRESQL
=============================

-- ============ GÉNÉRALISATION ============
-- Table de métadonnées pour les modules
CREATE TABLE module (
    id          SERIAL PRIMARY KEY,
    code        VARCHAR(50) UNIQUE NOT NULL,  -- 'STOCK', 'BIBLIO', etc.
    libelle     VARCHAR(100) NOT NULL,
    description TEXT,
    actif       BOOLEAN DEFAULT TRUE
);

-- ============ CATÉGORIES (hiérarchiques) ============
CREATE TABLE categorie (
    id              SERIAL PRIMARY KEY,
    module_id       INT REFERENCES module(id),
    code            VARCHAR(50) UNIQUE NOT NULL,
    libelle         VARCHAR(150) NOT NULL,
    categorie_parent_id INT REFERENCES categorie(id), -- hiérarchie
    description     TEXT,
    created_at      TIMESTAMP DEFAULT NOW()
);

-- ============ ARTICLE (entité principale) ============
CREATE TABLE article (
    id                    SERIAL PRIMARY KEY,
    categorie_id          INT REFERENCES categorie(id),
    code                  VARCHAR(50) UNIQUE NOT NULL,
    designation           VARCHAR(250) NOT NULL,
    description           TEXT,
    unite_mesure          VARCHAR(20) DEFAULT 'unité',
    -- Méthode de valorisation PAR article (chaque article peut avoir sa propre méthode)
    methode_valorisation  VARCHAR(10) DEFAULT 'CUMP'
                            CHECK (methode_valorisation IN ('FIFO','LIFO','CUMP')),
    stock_initial         DECIMAL(15,4) DEFAULT 0,
    stock_actuel          DECIMAL(15,4) DEFAULT 0,
    valeur_stock_actuelle DECIMAL(15,4) DEFAULT 0,
    cump_actuel           DECIMAL(15,4) DEFAULT 0,
    stock_min_alerte      DECIMAL(15,4) DEFAULT 0,
    actif                 BOOLEAN DEFAULT TRUE,
    created_at            TIMESTAMP DEFAULT NOW(),
    updated_at            TIMESTAMP DEFAULT NOW()
);

-- ============ LOT (brique FIFO/LIFO) ============
-- Chaque entrée crée un LOT distinct avec son propre PU
-- C'est la clé de tout FIFO et LIFO
CREATE TABLE lot (
    id                  SERIAL PRIMARY KEY,
    article_id          INT NOT NULL REFERENCES article(id),
    -- Référence vers le mouvement d'entrée qui a créé ce lot
    mouvement_entree_id INT,  -- sera mis à jour après insertion mouvement
    date_entree         DATE NOT NULL,
    quantite_initiale   DECIMAL(15,4) NOT NULL,
    quantite_restante   DECIMAL(15,4) NOT NULL,
    prix_unitaire       DECIMAL(15,4) NOT NULL,  -- PU d'achat du lot
    valeur_restante     DECIMAL(15,4) GENERATED ALWAYS AS
                        (quantite_restante * prix_unitaire) STORED,
    epuise              BOOLEAN DEFAULT FALSE,
    -- SOURCE : d'où vient ce PU ? (fournisseur, facture, BL, import...)
    source_reference    VARCHAR(100),  -- numéro bon de commande, facture
    source_type         VARCHAR(50),   -- 'ACHAT', 'TRANSFERT', 'AJUSTEMENT'
    source_document     VARCHAR(200),  -- description source
    created_at          TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_lot_article_date ON lot(article_id, date_entree, epuise);

-- ============ MOUVEMENT (entrée ou sortie) ============
CREATE TABLE mouvement (
    id                    SERIAL PRIMARY KEY,
    article_id            INT NOT NULL REFERENCES article(id),
    date_mouvement        DATE NOT NULL,
    type_mouvement        VARCHAR(10) NOT NULL CHECK (type_mouvement IN ('ENTREE','SORTIE','AJUSTEMENT')),
    quantite              DECIMAL(15,4) NOT NULL,
    -- Pour entrée : PU réel payé
    -- Pour sortie CUMP : CUMP du moment | Pour FIFO/LIFO : PU moyen pondéré de la sortie
    prix_unitaire_calcule DECIMAL(15,4),
    valeur_mouvement      DECIMAL(15,4),
    -- Snapshot après mouvement (pour reconstituer historique)
    stock_qte_apres       DECIMAL(15,4),
    valeur_stock_apres    DECIMAL(15,4),
    cump_apres            DECIMAL(15,4),
    -- Méthode utilisée pour ce mouvement
    methode_valorisation  VARCHAR(10) CHECK (methode_valorisation IN ('FIFO','LIFO','CUMP')),
    -- SOURCE du mouvement (traçabilité)
    source_reference      VARCHAR(100),  -- BL, BC, facture...
    source_type           VARCHAR(50),   -- 'VENTE', 'TRANSFERT', 'PERTE', 'RETOUR'
    source_tiers          VARCHAR(200),  -- client, fournisseur, département
    motif                 TEXT,
    created_at            TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_mouvement_article_date ON mouvement(article_id, date_mouvement);

-- ============ MOUVEMENT_LOT_SOURCE (traçabilité fine) ============
-- LA TABLE LA PLUS IMPORTANTE pour FIFO/LIFO
-- Pour chaque SORTIE, on trace quels lots ont été consommés
-- et en quelle quantité → c'est la SOURCE injectée dans la trace
CREATE TABLE mouvement_lot_source (
    id                  SERIAL PRIMARY KEY,
    mouvement_id        INT NOT NULL REFERENCES mouvement(id) ON DELETE CASCADE,
    lot_id              INT NOT NULL REFERENCES lot(id),
    -- Qté prélevée sur ce lot spécifique pour cette sortie
    quantite_prelevee   DECIMAL(15,4) NOT NULL,
    -- PU de ce lot au moment du prélèvement (injecté depuis lot.prix_unitaire)
    prix_unitaire_lot   DECIMAL(15,4) NOT NULL,
    valeur_prelevee     DECIMAL(15,4) GENERATED ALWAYS AS
                        (quantite_prelevee * prix_unitaire_lot) STORED,
    -- Référence source (reprend la source du lot d'origine)
    source_lot_reference VARCHAR(100),
    source_lot_type      VARCHAR(50),
    -- Ordre de consommation dans cette sortie (1er lot consommé, 2ème, etc.)
    ordre_consommation  INT DEFAULT 1,
    created_at          TIMESTAMP DEFAULT NOW()
);

-- ============ VUE ÉTAT STOCK GÉNÉRAL ============
CREATE VIEW v_etat_stock_general AS
SELECT
    a.id AS article_id,
    a.code,
    a.designation,
    c.libelle AS categorie,
    a.unite_mesure,
    a.methode_valorisation,
    a.stock_actuel,
    a.cump_actuel,
    a.valeur_stock_actuelle,
    -- Comptage des lots encore actifs
    COUNT(l.id) FILTER (WHERE NOT l.epuise) AS nb_lots_actifs,
    a.stock_min_alerte,
    CASE WHEN a.stock_actuel <= a.stock_min_alerte THEN TRUE ELSE FALSE END AS alerte_stock
FROM article a
LEFT JOIN categorie c ON a.categorie_id = c.id
LEFT JOIN lot l ON l.article_id = a.id
WHERE a.actif = TRUE
GROUP BY a.id, a.code, a.designation, c.libelle,
         a.unite_mesure, a.methode_valorisation,
         a.stock_actuel, a.cump_actuel, a.valeur_stock_actuelle,
         a.stock_min_alerte;

-- ============ VUE DÉTAIL MOUVEMENTS AVEC SOURCE ============
CREATE VIEW v_mouvement_detail AS
SELECT
    m.id AS mouvement_id,
    m.date_mouvement,
    a.code AS article_code,
    a.designation AS article_designation,
    m.type_mouvement,
    m.quantite,
    m.prix_unitaire_calcule AS pu,
    m.valeur_mouvement,
    m.stock_qte_apres,
    m.valeur_stock_apres,
    m.cump_apres,
    m.methode_valorisation,
    m.source_reference,
    m.source_type,
    m.source_tiers,
    -- Pour les sorties : détail des lots sources consommés
    STRING_AGG(
        'Lot#' || mls.lot_id || ' (' || mls.quantite_prelevee || 'u à ' ||
        mls.prix_unitaire_lot || ' / src:' || COALESCE(mls.source_lot_reference,'?') || ')',
        ' | ' ORDER BY mls.ordre_consommation
    ) AS detail_lots_source
FROM mouvement m
JOIN article a ON m.article_id = a.id
LEFT JOIN mouvement_lot_source mls ON mls.mouvement_id = m.id
GROUP BY m.id, m.date_mouvement, a.code, a.designation,
         m.type_mouvement, m.quantite, m.prix_unitaire_calcule,
         m.valeur_mouvement, m.stock_qte_apres, m.valeur_stock_apres,
         m.cump_apres, m.methode_valorisation,
         m.source_reference, m.source_type, m.source_tiers;

III. ALGORITHMES MÉTIER (Java)
=============================

--- Interface Strategy ---
public interface ValorizationStrategy {
    /**
     * Calcule et enregistre une sortie de stock.
     * Retourne la liste des MouvementLotSource générées (la trace).
     */
    ResultatSortie calculerSortie(
        int articleId,
        BigDecimal quantiteSortie,
        Connection conn
    ) throws StockInsuffisantException;
}

public class ResultatSortie {
    BigDecimal prixUnitaireMoyen;  // PU moyen de la sortie
    BigDecimal valeurTotale;
    List<MouvementLotSource> lotsConsommes;  // TRACE SOURCE
}

--- FIFO Strategy ---
public class FifoStrategy implements ValorizationStrategy {
    // 1. Récupérer lots ORDER BY date_entree ASC, id ASC WHERE epuise=FALSE
    // 2. Boucler tant que quantité restante > 0 :
    //    a. Prélever min(lot.quantite_restante, quantite_restante_a_sortir)
    //    b. Créer MouvementLotSource avec {lot_id, qte, pu_lot, source_lot}
    //    c. Déduire lot.quantite_restante
    //    d. Si lot.quantite_restante = 0 → lot.epuise = TRUE
    // 3. PU moyen sortie = SUM(valeur_prelevee) / quantite_sortie
}

--- LIFO Strategy ---
public class LifoStrategy implements ValorizationStrategy {
    // Identique à FIFO mais ORDER BY date_entree DESC, id DESC
}

--- CUMP Strategy ---
public class CumpStrategy implements ValorizationStrategy {
    // 1. PU_sortie = article.cump_actuel
    // 2. Valeur_sortie = quantite × cump
    // 3. Pas de consommation de lot précis → créer 1 seul MouvementLotSource
    //    fictif pointant vers le "lot CUMP virtuel" (ou null)
    // 4. Mettre à jour article.stock_actuel et valeur_stock
    //    → nouveau CUMP = (valeur_stock - valeur_sortie) / nouveau_stock
}

--- Recalcul CUMP après entrée ---
BigDecimal nouveauCump =
    (articleValeurActuelle.add(valeurEntree))
    .divide(articleStockActuel.add(qteEntree), 4, HALF_UP);

IV. INTERFACES JAVA SWING — DÉTAIL FENÊTRES
=============================

--- A. Fenêtre Gestion Articles ---
Composants :
- GenericTableModel<Article> avec colonnes :
  [Code, Désignation, Catégorie, Unité, Méthode, Stock, CUMP, Valeur Stock, Alerte]
- Toolbar : [Nouveau] [Modifier] [Supprimer] [Rechercher] [Exporter]
- GenericFormPanel (formulaire auto-généré depuis ColumnDef[])
- Le champ "Méthode de valorisation" est un JComboBox : FIFO | LIFO | CUMP
- Le champ "Catégorie" est un JComboBox dynamique chargé depuis DB

--- B. Fenêtre Saisie Mouvement ---
Deux onglets : ENTRÉE | SORTIE

[Onglet ENTRÉE]
- Sélection article (JComboBox + recherche rapide)
- Date mouvement (JDateChooser)
- Quantité (JFormattedTextField décimal)
- Prix unitaire (obligatoire pour entrée)
- Valeur calculée auto = qte × PU (champ readonly)
- SOURCE :
  * Type source (JComboBox : ACHAT, TRANSFERT, RETOUR, AJUSTEMENT)
  * Référence source (JTextField : n° facture, BL...)
  * Tiers (JTextField : fournisseur, département...)
- Motif (JTextArea)
- [Bouton VALIDER ENTRÉE]
  → appelle StockService.enregistrerEntree()
  → crée 1 Lot + 1 Mouvement
  → recalcule CUMP article

[Onglet SORTIE]
- Sélection article (affiche stock actuel + CUMP + nb lots)
- Date mouvement
- Quantité (validation : qte <= stock_actuel)
- Méthode de valorisation :
  * Si article a méthode fixée → affichée en lecture seule
  * Sinon → JComboBox : FIFO | LIFO | CUMP (choix à la sortie)
- Prévisualisation sortie (JPanel dynamique) :
  → Dès que l'utilisateur tape la quantité, afficher en temps réel :
     la liste des lots qui seraient consommés (selon méthode)
     avec leur PU respectif et la valeur totale estimée
     → c'est le FEEDBACK visuel de la SOURCE avant validation
- SOURCE de la sortie :
  * Type (VENTE, CONSOMMATION, PERTE, TRANSFERT)
  * Référence (n° bon de sortie)
  * Tiers (client, département destinataire)
- [Bouton VALIDER SORTIE]
  → appelle StockService.enregistrerSortie(article, qte, methode, source)
  → exécute la Strategy (FIFO/LIFO/CUMP)
  → crée Mouvement + MouvementLotSource (trace)
  → met à jour stock et lots dans une Transaction SQL

--- C. Fenêtre État Stock Général ---
- JTable chargée depuis v_etat_stock_general
- Colonnes : Code | Désignation | Catégorie | Méthode | Stock | CUMP | Valeur | Alerte
- Lignes en rouge si alerte_stock = TRUE
- Filtre en haut : par catégorie, par méthode, par alerte
- Double-clic sur une ligne → ouvre Fenêtre Détail Article

--- D. Fenêtre Détail Article (clique sur ligne) ---
Layout JSplitPane :
- Panneau HAUT : fiche article (lecture seule)
  + stock actuel + CUMP + valeur stock + nb lots actifs
- Panneau BAS GAUCHE : Historique mouvements
  JTable chargée depuis v_mouvement_detail WHERE article_id = ?
  Colonnes : Date | Type | Qté | PU | Valeur | Méthode | Stock après | Source tiers | Référence
  → Entrées en VERT, Sorties en ROUGE
- Panneau BAS DROITE : (apparaît quand on sélectionne une SORTIE dans le tableau)
  Détail des lots sources consommés :
  JTable avec : Lot# | Date entrée lot | Qté prélevée | PU lot | Valeur | Source lot
  → Ici apparaît la colonne SOURCE INJECTÉE :
     d'où venait ce lot (fournisseur, référence achat, etc.)
     qui le relie à sa trace d'entrée d'origine

V. RÈGLES TECHNIQUES CRITIQUES
=============================

1. TRANSACTIONNALITÉ OBLIGATOIRE
   Toute saisie de mouvement doit être dans une transaction SQL :
   BEGIN → insert mouvement → update lots → update article → commit
   En cas d'échec → ROLLBACK total. Aucune mise à jour partielle.

2. COLONNE SOURCE — INJECTION DE TRAÇABILITÉ
   Pour chaque sortie enregistrée dans mouvement_lot_source :
   - Recopier la source_reference et source_type du LOT d'origine
   - Ainsi le rapport final peut afficher :
     "Ce produit vendu le 04/05 provenait d'un achat du 01/05
      facture F-2024-001, fournisseur SODIAT"
   C'est l'injection source_lot_reference ← lot.source_reference

3. PRÉVISUALISATION TEMPS RÉEL
   Lors de la saisie sortie, simuler la strategy en lecture seule
   (sans écrire en DB) et afficher :
   "Avec FIFO : Lot#1 (5u×100) + Lot#2 (8u×110) = 1380"
   → Utiliser Strategy.simulerSortie() (lecture seule)

4. SNAPSHOT OBLIGATOIRE
   Après chaque mouvement, stocker dans mouvement :
   stock_qte_apres, valeur_stock_apres, cump_apres
   → Permet reconstitution historique sans recalcul

5. GÉNÉRALISATION UI
   GenericFormPanel prend un List<ColumnDef> en entrée.
   ColumnDef contient : {fieldName, label, type, required, editable, comboValues}
   Les JComponent sont générés dynamiquement selon le type.
   → Pour ajouter un champ Article, modifier uniquement ArticleMetadata.java

6. ALERTE STOCK
   SwingWorker en background toutes les 5 minutes :
   vérifier articles où stock_actuel < stock_min_alerte
   → notification visuelle (icône rouge dans barre de statut)

=============================
VI. CONTRAINTES NON NÉGOCIABLES
=============================

- Aucun calcul de stock "à la volée" depuis l'historique des mouvements
  → Toujours lire article.stock_actuel (mis à jour en temps réel)
- Aucune modification rétroactive d'un mouvement validé
  → Pour corriger : créer un mouvement d'AJUSTEMENT avec motif
- La méthode de valorisation d'un article ne peut changer
  après la première entrée (bloquer le champ UI si lots existants)
- Tout prix est stocké en DECIMAL(15,4) — jamais de FLOAT
- Les IDs sont toujours SERIAL PostgreSQL — jamais UUID générés en Java
- Chaque connexion JDBC utilise un connection pool (HikariCP recommandé)
